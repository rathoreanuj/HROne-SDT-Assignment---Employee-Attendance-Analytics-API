# REVIEW.md — Starter `app/main.py` Code Review

Defects found in the original starter code:

| # | Where (function / line) | What is wrong | How you'd notice it | How it was fixed |
|---|---|---|---|---|
| 1 | `health()` | Returns `{"status": "ok"}` without pinging MongoDB. The spec says "returns 200 only if MongoDB answers a ping, otherwise 503." A dead database would still return 200. | Start the app with no Mongo running; `/health` returns 200 instead of 503. | Added `client.admin.command("ping")` inside a try/except; raises HTTP 503 on failure. |
| 2 | `create_employee()` — race condition | Uses check-then-insert: `find_one` then `insert_one`. Two concurrent requests with the same `emp_code` can both pass the check and both insert, violating the unique guarantee. | Send two simultaneous POST /employees with the same `emp_code`; both may return 201. | Rely solely on a MongoDB unique index on `emp_code`; catch `DuplicateKeyError` and return 409. |
| 3 | `create_employee()` — `created_at` naive | `datetime.now()` (no tz) produces a naive local datetime. PyMongo stores it but the value is ambiguous and wrong on servers not in local time. | On a UTC server the stored time is off by the server's local offset. | Changed to `datetime.now(tz=timezone.utc)`. |
| 4 | `list_employees()` — wrong skip | `skip = page * page_size` skips page 1 of results for `page=1` (should skip 0 for page 1). E.g., page=1 skips 20 docs; page=2 skips 40. | `GET /employees?page=1` returns the second page of data. | Changed to `(page - 1) * page_size`. |
| 5 | `list_employees()` — total counts wrong set | `count_documents({})` ignores the `department` filter, so `total` is always the full collection size regardless of the filter applied. | Filter by department; `total` in the response is larger than `items` would imply. | Changed to `count_documents(q)` where `q` is the same filter used for the query. |
| 6 | `punch_in()` — `emp` not checked for None | If the `emp_code` doesn't exist, `find_one` returns `None`; the code proceeds and crashes with `TypeError` on `emp["shift_start"]`. | POST punch-in with an unknown `emp_code`; server returns 500 instead of 404. | Added `if not emp: raise HTTPException(404, ...)` immediately after the lookup. |
| 7 | `punch_in()` — naive timestamp conversion | `datetime.fromtimestamp(ms / 1000)` (no tz) produces a naive local datetime. On a UTC server the stored time is off by the IST offset (5h30m). | Punch-in time stored in MongoDB is wrong by 5.5 hours on a UTC host. | Replaced with `ms_to_dt(ms)` which uses `fromtimestamp(..., tz=timezone.utc)` and truncates to seconds. |
| 8 | `punch_in()` — attendance date wrong | `ts.date().isoformat()` uses the **local** date of the naive datetime, ignoring R1 (IST calendar date, overnight shift rule). | Night-shift punch-ins in IST (e.g., 22:00 IST = 16:30 UTC) would get the UTC date, and overnight shifts would never be detected. | Replaced with `attendance_date_for_punch(ts, shift_start, shift_end)` which converts to IST and applies the overnight-shift rule. |
| 9 | `compute_late_minutes()` — grace period boundary wrong | The condition `if minutes > 10` means exactly 10 min late is counted (returns 10). R2 says "strictly more than 10:00"; 10 min exactly is not late. | A punch-in exactly 10 minutes after shift start returns `late_minutes=10` instead of 0. | Changed condition: late only when `elapsed_sec > 600` (strictly more than 10 minutes). |
| 10 | `compute_late_minutes()` — incorrect base datetime | `punch_in.replace(hour=h, minute=m, ...)` replaces the hour/minute on the punch_in datetime (which is UTC), computing an offset from UTC midnight, not from IST shift start. This is wrong for any shift. | Any shift start other than 00:00 UTC gives wrong late_minutes. | Rebuild shift_start as an IST-aware datetime anchored to the IST attendance date, then compare with the IST punch-in time. |
| 11 | `compute_overtime()` — missing `>= 30` minimum | Returns any positive difference, but R3 says overtime only when >= 30 minutes; otherwise 0. | A punch-out 5 minutes after shift end returns `overtime_minutes=5` instead of 0. | Added `if elapsed < 30 * 60: return 0`. |
| 12 | `compute_work_hours()` — wrong rounding | `round(..., 2)` uses Python's banker's rounding (round-half-even). R4 requires half-up rounding. | 9.125 → round gives 9.12 (banker's), half-up gives 9.13. | Replaced with `half_up(secs / 3600, 2)` using `math.floor(x * 100 + 0.5) / 100`. |
| 13 | `punch_in()` — response leaks `id` field | The code sets `doc["id"] = str(res.inserted_id)` and returns it. The API contract has no `id` field in `AttendanceRecord`. | Response body contains an `id` key not in the schema. | Removed; response is built with `record_to_api(doc)` which omits `_id`. |
| 14 | `list_attendance()` — loads entire collection | `find(q)` with no `.limit()` fetches all matching documents into Python memory, then sorts and paginates in Python. Unusable on 100k+ records; violates the spec's "must stay fast". | On a large collection the endpoint times out or runs out of memory. | Replaced with server-side `.sort().skip().limit()` and `count_documents(q)` for total. |
| 15 | `list_attendance()` — `_id` leaks in response | `d["id"] = str(d.pop("_id"))` renames `_id` to `id` and includes it in the response. The schema has no `id` field. | Response items contain `id` instead of the contract fields. | Excluded `_id` from projection; response built with `record_to_api(d)` which converts datetimes to epoch ms. |
| 16 | All endpoints — datetime fields not serialized | MongoDB BSON `datetime` objects are returned directly in dicts. FastAPI serializes them as ISO strings, but the contract requires **epoch milliseconds** (integers). | `punch_in`, `punch_out`, `created_at`, `history[].at` return ISO strings instead of integers. | Added `record_to_api()` / `employee_to_api()` helpers that convert all `datetime` fields to `dt_to_ms()`. |
| 17 | `punch_in()` — no validation of `status` | Any string is accepted; no check that it is one of `PRESENT`, `WFH`, `ON_DUTY`. | Sending `status: "ABSENT"` creates an ABSENT record via punch-in, violating the spec. | Added `field_validator` in `PunchInRequest`; only presence statuses are accepted. |

**Not a defect — kept as-is:**
- Using `load_dotenv()` at module level: acceptable; environment variables set externally still win (dotenv skips existing env vars by default).
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct definition of IST offset.
